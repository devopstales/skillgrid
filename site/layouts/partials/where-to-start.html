Where to start

Three starting points. Same loop after that.

The first skill you run depends on where the project is. After the first loop, every change is the same: blueprint → slice → verify → ship.

Greenfield
New project

Interview the idea, blueprint the decision, set up the project, then onboarding reads a real project instead of an empty folder.

/interviewing /writing-blueprints set up project /onboarding loop
Brownfield
Existing codebase

Onboarding first, so every skill understands your stack and conventions, then blueprint the next slice on top of what exists.

/onboarding /writing-blueprints loop
Monorepo
Several projects, one repo

Everything scopes to the target workspace, which has its own AGENTS.md, config, stack and commands. A change to one app never reaches into another.

per workspace nested AGENTS.md
