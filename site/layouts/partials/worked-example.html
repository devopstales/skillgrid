A worked example

One idea, followed all the way to shipped.

A small app where people sign in and keep their own to-do list. Brand new project, so it touches almost every stage, and every question the workflow asks along the way.

01
Interview the idea
A design-tree interview in rounds until a weighted clarity gate passes. The domain model (glossary, ADRs) starts here.
02
Blueprint the decision
writing-blueprints. It works out what it can, asks only what you alone know, recommends the rest. One-way-door tags, no placeholders.
03
Slice the build
slicing breaks the blueprint into vertical tracer-bullet tickets with dependency edges and execution waves.
04
Onboard the project
onboarding detects the stack, testing, tracker and security posture, writes .skillgrid/config.yaml + the AGENTS.md block.
05
Execute the slices
subagent-execution runs a fresh implementer per task, TDD throughout, per-task review, then a final QA gate + whole-branch review.
06
Prove it runs
qa runs goal-backward verification: sign up, sign in, see only your own list. 4-state gate (PASS / CONCERNS / FAIL / WAIVED).
07
Write the tests
test-driven-development keeps the iron law: no production code without a failing test first. The acceptance suite moves to Accepted.
08
Get a second opinion
requesting-code-review dispatches two parallel reviewers (standards + spec) on a different model than the implementer's.
09
Write it up
document reads the real commits and diff, never memory: PR body, changelog, release note.
10
Close the loop
ship integrates to the base branch and moves the spec to archive. reflect writes report.md. The loop is closed; clear the session.
