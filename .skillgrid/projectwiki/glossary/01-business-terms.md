# Business glossary

Domain, product, and workflow terms for the mnemonic project. One row per term.

| Term | Definition | Use When | Avoid |
| --- | --- | --- | --- |
| projectwiki | The project's git-tracked OKF markdown vault (`.skillgrid/projectwiki/`) plus the mnemonic subsystem that indexes, serves, and validates it. | When discussing the Phase 3 wiki pillar or its data. | "the wiki", "docs DB", "knowledge base" (overloaded) |
| vault | The git-tracked `.skillgrid/projectwiki/` directory in the repo — source of truth for wiki content. | When distinguishing content ownership from derived index state. | "store" (collides with DB store), "home" |
| page | One concept in the vault: one markdown file in a page-type folder (`decisions/`, `invariants/`, `workflows/`, `glossary/`, `reference/`). | When discussing wiki content units, their types, and lifecycle. | "article", "doc", "note" |
| learning loop | The pi-hermes pattern: session learnings (corrections, insights, procedural skills) promote into durable, retrievable artifacts. | When discussing how wiki/memory content grows from agent sessions. | "auto-write"; "consolidation" (that means merging existing entries) |
