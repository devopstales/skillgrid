# Glossary — Business

Domain, product, workflow, and business terms used across skillgrid changes.

| Term | Definition | Use When | Avoid |
| --- | --- | --- | --- |
| Step | A sequenced unit of an SDD change that ships one testable behaviour slice (Step Blueprint → `@step-NN`). | Writing `change.md` Step Blueprint / Per-step WHAT, `tasks.md` sections, `acceptance.feature`. | "phase" (overloaded with sdd phases), "stage". |
| Change | A self-contained SDD unit tracked by a 3-digit NNN number, authored as `change.md` through `archive/`. | Referencing any SDD change in docs or skills. | "ticket", "PR" (broader scope). |
| Artifact | A file persisted by an SDD phase (`research.md`, `change.md`, `tasks.md`, `acceptance.feature`, archive report). | Cross-referencing phase outputs. | "document", "doc" (too generic). |
| Companion Glossary Reference | Resolved in SDD v3 — legacy `intent.md`, `plan.md`/`plan-glossary-reference.md`, and `intent-glossary-reference.md` were folded into `briefing.md` (v3) and `blueprint.md`; the single-artifact contract is `briefing.md` → `blueprint.md`. Do not create `*-glossary-reference.md`. | Only when reading legacy pre-v3 changes. | Creating new companion files. |
| Clone-Private Identity Binding | One-time project id written into the git common-dir and reused on every later resolve for that clone (including linked worktrees). | Mnemonic project resolution (002); Engram-parity identity. | "project name", path-hash id, remote basename alone. |
| Child Auto-Promote | When a cwd is the parent of exactly one git repo, resolution promotes that child as the project (with a soft warning). | Parent-directory resolve behaviour (002). | Blind directory-hash fallback. |
| Ambiguous Project | Resolution outcome when a cwd parents multiple git repos; callers receive `AvailableProjects` instead of a silent fallback id. | `ErrAmbiguousProject` / `MNEMONIC_PROJECT` recovery (002). | Silent `directory-hash` pick. |
| Cross-Store Recall | Searching every Mnemonic SQLite under the store dir and merging/re-ranking hits (`all_projects`). | `mem_search(all_projects=true)` (002). | Per-store-only search. |
| Observation Lifecycle | Pinning, expiry, duplicate count, and recency columns that affect recall ordering and exclusion. | Lifecycle parity vs Engram (002). | Soft-delete alone; review_after cycle alone. |
| Long-term Memory | A durable compacted memory entry (L2 durable on commit; L0/L1 async) persisted by explicit `mnemonic_commit` into `long_term_memories`. | `mnemonic_commit`, default `semantic_search` corpus; change 003. | "observation", "mem_save" (session-scoped curated notes); auto-commit on session end. |
| Fact Memory | A structured store of atomic facts (importance, scope, soft delete, decay) beside `mem_*` observations — not an observation overlay. | Hermes memory tools (`fact_add`/`fact_search`/`fact_forget`/`fact_decay`); 004-hermes-memory. | "observation", "mem_save", "Long-term Memory" (different stores). |
| Agent Skill | An agent-writable, searchable, sandbox-executable script/prompt stored as FS + `skills` table metadata. | Hermes skill tools (`write_skill`/`search_skills`/`use_skill`/`list_skills`); 004-hermes-memory. | `.agents/skills` SDD skill packs; "skill" alone when ambiguous. |
| Session Handoff | A Cleave-style continuity package: progress, knowledge, and next-prompt files plus a recorded handoff row so a task can resume in a new session. | `session_handoff` / `session_resume`; `.skillgrid/.cleave/`; 006-structured-session-handoff. | "Long-term Memory" (durable recall via `mnemonic_commit`); Engram `mem_session_*` summaries alone. |
| Session Relay | The subsystem that records, resumes, and status-checks Session Handoffs (schema, MCP, `.cleave/` FS, CLI, optional watchdog). | Naming the 006 capability set; cross-session task continuity. | "session" alone; Engram session lifecycle; Tiered Storage. |
| Hub Product | The whole `skillgrid` product as one shippable unit: the `skillgrid` CLI binary plus the Mnemonic Engine it runs, the Distribution Surface it serves on, and the Hub Content (skills/hooks/config) it installs. The PRD scope. | `.skillgrid/reference/00-prd.md`; product framing; scope decisions. | "skillgrid-cli" (the binary alone); "Mnemonic" (the engine alone, a component of this). |
| v1.0 Line | The target-state definition for the first committed release: "the engine is trustworthy" — install idempotent across agents, `doctor --strict` green, MCP/HTTP stable, index/search/code-intel reliable, mem/session/trail working; the embedded UI dashboard remains Phase 2 (stub pages). | `.skillgrid/reference/00-prd.md` Release line; roadmap item scoping. | "MVP" (overloaded); "release 1" (no target-state definition). |
| Development Workflow | The ordered step-by-step execution guide for Delivery changes: which skill to invoke, subagents to dispatch, MCP tools to use, files to write, and where the user gates are, per SDD phase (Steps 0–10); the executable complement to the SDD Pipeline concept page. | Authoring or executing a Delivery change top-to-bottom; onboarding a new session to the pipeline. | Reaching for it for Specialist or Q&A requests (they do not enter the pipeline); treating it as a replacement for the per-phase skill bodies. |
| Goldfish (EGM Review Model) | The review model ported from the Elephant-Goldfish Model (google/elephant-goldfish-model): fresh-context, isolated, read-only "Goldfish" reviewers attack the target while the "Elephant" (main agent / owner side) resolves findings. Four skillgrid tracks: brainstorming shootdown (Track A), writing-blueprints plan review (Track B), drafting disciplines (Track C), and the qa drift-report mode (Track D); rounds recorded in the review-ledger reference. | Describing any of the four review/drafting tracks (2026-11-02-egm-goldfish-brainstorm-shootdown); ADRs 0062-0065. | "code review" (the after-code `code-review` skill is a separate gate); "3-stage subflow" (ADR-0054, superseded by 0063). |
| Shootdown | The 6-lens fresh-context Goldfish idea-validation subflow of `brainstorming` (Track A): runs after the feasibility check, before the ADR manifest; a blocker-disposition gate precedes spec writing; findings land in `briefing.md`'s `## Shootdown Findings`. Lens rubrics are the 6 `lens-*.md` persona briefs (R1 attack questions), not the review personas. | Track A work in `brainstorming`; briefing shootdown sections. | "brainstorm review" (pre-port name); "plan review" (Track B — the blueprint-side half). |
| Drift Report | A mode of `qa` (Track D): periodic, user-invoked, advisory — never the four-state gate, never a CI check. Classifies spec-vs-code divergence into exactly 4 categories (missing features, logic short-cuts, architectural divergence, interface dependency), reuses the Goldfish resolution flow, renders `drift-report.md`. Detail in `qa/references/drift-report.md`. | Track D drift checks on a spec dir or project-wide. | "new top-level skill" (ADR-0064: it is a qa mode); "CI check" (agent-driven, on-demand only). |
| Persona Brief | One of the 13 shared Goldfish reviewer-persona files in `.agents/skills/_shared/elephant-goldfish/` (7 review briefs + 6 BRAINSTORM-mode lens briefs); each is ≤150 lines, self-contained read-only, and names its role, isolation mandate, audit questions, and output format. Cited (not restated) by the tracks that dispatch them. | Authoring or citing a Goldfish reviewer's instructions; Track A/B dispatch. | "agent definition" (a brief is a prompt file, not a subagent type); duplicating brief text into a track file (cite-don't-restate). |
