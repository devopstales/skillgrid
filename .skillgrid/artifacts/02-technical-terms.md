# Glossary — Technical

Architecture, implementation, platform, and protocol terms used across skillgrid changes.

| Term | Definition | Use When | Avoid |
| --- | --- | --- | --- |
| Module | Anything with an interface and an implementation; deliberately scale-agnostic (function, class, package, slice). | `change.md` Architecture Decisions. | "unit", "component", "service". See `codebase-design` skill. |
| Interface | Everything a caller must know to use a module correctly: type signature, invariants, ordering constraints, error modes, configuration, performance. | `change.md` Architecture Decisions. | "API", "signature" (too narrow). See `codebase-design` skill. |
| Seam | The location at which a module's interface lives; a place where you can alter behaviour without editing in that place. | `change.md` Architecture Decisions, `sdd-apply` testability checks. | "boundary" (overloaded with DDD). See `codebase-design` skill. |
| Adapter | A concrete thing that satisfies an interface at a seam; describes role, not substance. | `change.md` Architecture Decisions. | "implementation" (overlap; use adapter only when seam is the topic). |
| Depth | Leverage at the interface: the amount of behaviour a caller exercises per unit of interface they have to learn. | `change.md` Architecture Decisions (the "deep vs shallow" check). | "complexity" (depth is leverage, not bulk). |
| Artifact Store Mode | The persistence contract for SDD artifacts: `hybrid` (filesystem + Mnemonic) is the only mode for every phase. | Referencing the persistence layer in any SDD skill. | "store", "DB" (too generic). |
| Project Handle | Opened single-project Mnemonic seam: one SQLite store plus accessors to memory/web (and related) for that project id; callers open once per request. | Deepening the mnemonic facade (`007`); MCP/HTTP single-project paths. | "connection", "session" (overloaded); the wide `service.Service` open-delegate wrappers. |
| Topic Key | A stable string used to upsert Mnemonic observations (`mem_save` with same key updates the same row). | Persisting evolving decisions, conventions, or bugfix lineage. | "key" (ambiguous). |
| Step Folder | Legacy pre-v3 layout `docs/skillgrid/changes/<NNN-slug>/steps/<NN-name>/`. v3 keeps steps as sections inside change-level `tasks.md` + `@step-NN` Features. | Reading legacy changes only. | Creating new `steps/` trees for v3 work. |
| Acceptance Feature | Change-level Gherkin `acceptance.feature` with Features tagged `@step-NN`; the executable contract per step. | `sdd-spec`, `sdd-apply`, `sdd-verify`. | "spec file"; per-step companion features (legacy). |
| Per-step Verification | The `### Verification` block inside each step section of `tasks.md`, with `PASS` / `PASS WITH WARNINGS` / `FAIL`. | `sdd-verify`, `sdd-archive` gate. | "test report" (broader); legacy `verification.md`. |
| Seed Alias | Auto-inserted `project_aliases` row mapping a prior path/remote key to the new canonical project id. | Identity binding create path (002). | Manual-only unify without seed. |
| Embedding Recall | Optional cosine search over observation embeddings, fused with FTS5 when `MNEMONIC_EMBED` is enabled. | Observation semantic recall (002 P4). | Code-index Hybrid Search; memory-only without fusion. |
| Reciprocal Rank Fusion | Rank merge that combines independent result lists (FTS5 + vector) without requiring calibrated scores. | `mem_search` embedding fusion (002). | Score-sum merge; replacing FTS5. |
| Hybrid Search | Multi-signal code retrieval that fuses identifier-aware FTS, deterministic similarity signals, and optional dense embeddings. | Code-intelligence intents/plans (e.g. 005); ranking and MCP search tools. | Memory-only `semantic_search` (003); plain `code_search` chunk FTS. |
| Symbol | A code unit keyed by qualified name (function, method, type, etc.) with path, kind, and span metadata. | Graph index, orientation tools, hybrid ranking units. | "chunk" (line window); memory observation. |
| Edge | A typed, directed relation between symbols with a confidence label and optional properties. | Call graph, dependents, implementors, hierarchy. | Undirected "link"; memory association. |
| Extractor | A per-language adapter that turns a source file into symbols and edges (tree-sitter primary, regex fallback). | Index pipeline; language Tier-1 rollout. | "parser" alone (must also emit graph). |
| Confidence Label | Trust class on an edge: `EXTRACTED`, `INFERRED`, or `AMBIGUOUS`. | Graph tools and resolver transparency. | Free-form score without a label. |
| Index Freshness | Per-path (and result-level) metadata stating whether indexed bytes still match the working tree. | Staleness banners, `index_status`, reindex UX. | Binary empty-index "stale" from chunk `code_status` alone. |
| Identifier-Aware FTS | FTS5 tokenization that splits camelCase and snake_case so symbol names match partial identifiers. | Symbol search and hybrid keyword channel. | Trigram-only `chunks_fts` without identifier split. |
| Tiered Storage | Progressive L0 (abstract) / L1 (overview) / L2 (full details) content held as filesystem sidecars with SQL path columns (`tiered_contents`). | Mnemonic recall design, `migrate --tier`, content-write seam after `mnemonic_commit`. | "summary files", "compressed memory" (vague). |
| Retrieval Trail | A persisted record of a retrieval: query, directories traversed, files read, and final result path (`retrieval_trails`). | Debugging why an agent missed context; `skillgrid trail`. | "search log", "audit log" (broader). |
| Semantic Search | Ranked L1 recall over tiered / long-term content via Pure Go embeddings (title/L0 fallback when vectors are absent); corpus filter defaults to LTM-only. | `semantic_search` MCP tool (separate from `mem_search`); `load_full_details` for L2. | "FTS search", "mem_search" (observation FTS only). |
| Dashboard | The embedded SPA served at `GET /` by `skillgrid serve`, covering Memory, Backlog, Code, and Sessions tabs. | `009-web-admin-dashboard`; operator-facing serving docs. | "webui" (vague); "admin panel" (interchangeable but prefer Dashboard in artifacts). |
| Backlog Bridge | The `internal/mnemonic/http/backlog` adapter that shells out to the `backlog` CLI (`--json`) and translates its versioned JSON to HTTP responses. | `009-web-admin-dashboard` step 02; any future HTTP↔CLI adapter. | "backlog parser" (it does not parse `.backlog` files directly). |
| Write-Gated Route | An HTTP route protected by the existing `SKILLGRID_HTTP_TOKEN` bearer check (`requireWriteAuth`); reads stay open. | `skillgrid serve` API docs; threat-matrix authz rows. | "auth" (ambiguous); implying read routes are gated. |
| Show-Numbers Table Twin | Every dashboard data widget has a toggle that renders the raw JSON/table behind the visual; the table is the source of truth, the visual is a convenience view. | `009-web-admin-dashboard`; any future admin UI widget. | "debug view" (implying it's non-primary); "raw data" (vague). Pattern source: codegraph telemetry dashboard. |
| Per-Widget Error Isolation | Each dashboard widget owns its own fetch + error render; a failed endpoint kills that widget only, never the tab or page. | `009-web-admin-dashboard`; any future admin UI. | "graceful degradation" (broader, implies the whole page survives); "lazy loading" (about when, not how-failure). |
| Forward-Compat Placeholder | A UI panel that renders a fallback today and is the designated mount point for a capability that depends on a future change. | `009` graph panel (awaits 010); any "coming in NNN" UI slot. | "stub" (implies throwaway); "feature flag" (that's a toggle, not a layout slot). |
| Execution Ledger | The gitignored file that owns a live run: `.skillgrid/sdd/<plan>/progress.md`, or `parallel-ledger.md` for a wave's rows. It holds task status, `Owns:`, `Needs:`, rulings, and gate results. | Dispatch, resume, and compaction recovery (ADR-0020). | Team Task; an observation; a Backlog task. |
| Execution Progress | One upserted Mnemonic observation at `skillgrid/{YYYY-MM-DD-<topic>}/execution-progress`. The body names the Execution Ledger path and the current tail. | Finding a run from a fresh session when the workspace path is not yet open (ADR-0020). | A copy of the ledger; the teams task queue. |
| Team Task | A row in the Mnemonic teams tables: SQL status and paths, with brief/output markdown under `.skillgrid/files/`. | The hybrid-teams MCP/HTTP plane. | The Execution Ledger. SDD dispatch does not spawn or claim Team Tasks (ADR-0020). |
| Team Member | An agent role row on a team (lead, developer, reviewer, etc.) that can be assigned tasks or submit reviews. | `team_members` table; pull/claim and review authorship. | Human user; generic "agent" without team binding. |
| Agent Review | A peer review of a Team Task (spec compliance or code quality) with a passed flag and comments markdown path. | `agent_submit_review`; `reviews` table under teams schema. | Memory observation `mem_review` / `/memory/reviews` lifecycle. |
| Inbox | Unread agent-to-agent messages for a Team Member, with subject in SQL and body markdown on disk. | Messages table / future inbox MCP; HTTP message CRUD. | Email inbox; MCP tool list; observation timeline. |
| Store Pooling | Cached `ProjectHandle` by project ID with refcounted close; eliminates N+1 SQLite opens across requests. | `014` store-pooling step; MCP/HTTP concurrent requests. | "connection pool" (too generic); "session" (overloaded). |
| Trigram FTS | FTS5 query splitting into 3-char trigrams for partial-match recall; supports `*` prefix wildcard. | `014` fts-trigram step; `mem search --mode trigram|prefix`. | "phrase matching" (exact only); "wildcard search" (too vague). |
| TTL Soft-Expiry | Auto-set `expires_at` on observation save (7-day default); `TTLRetire` soft-deletes expired rows. | `014` ttl-defaults step; `skillgrid mem expire`. | "hard delete" (irreversible); "auto-cleanup" (too vague). |
| LLM Extraction | LLM-based passive learning extraction with regex fallback; called by `CapturePassive`. | `014` llm-extraction step; `mem save` passive input. | "passive extraction" (ambiguous); "auto-learn" (too vague). |
| Multi-Embedder | Support for `ollama`, `local`, `onnx`, `external`, `off` embedder providers; config-driven via `indexing.yaml`. | `014` multi-embedder step; `skillgrid embedding-status`. | "embedder" (singular); "model" (ambiguous). |
| Parallel Cross-Project Search | Concurrent `SearchObservationsAll` with bounded goroutine pool; results merged by cross-store rank. | `014` parallel-search step; `mem search all_projects=true`. | "batch search" (sequential); "multi-search" (ambiguous). |
| Triple-Store Cross-Linkage | Relational + Vector + Graph stores cross-linked via `graph_ref` column and `symbol_embeddings` bridge table; every observation has both a vector embedding and a codeindex graph node representation; queries traverse observation→symbol→embedding→related observations via SQL JOIN. | `014` triple-store-linkage step; `mem search` cross-link queries. | "graph database" (too broad); "embedding index" (only one dimension). |
| Self-Improvement (`improve()`) | Re-weight observations by `retrieval_usage`; high-usage observations rank higher in `mem_search`; never-accessed observations decay over time; based on cognee's `improve()` pattern. | `014` improve-loop step; `mem search` re-ranking. | "feedback loop" (too vague); "machine learning" (no ML). |
| Session-to-Graph Promotion | L0/L1 session summaries automatically create permanent graph nodes in codeindex on `SessionEnd`; links session observations via `graph_ref`. | `014` session-promotion step; `SessionEnd` handler. | "session save" (no graph); "graph creation" (missing session trigger). |
| Temporal Knowledge Graph | Graph edges with `valid_from`/`valid_to` UNIX timestamp columns; expired edges hidden from queries but preserved for history; based on cognee's temporal knowledge graphs. | `014` temporal-graph step; `mem graph` CLI. | "versioned graph" (implies full versioning); "history table" (too narrow). |
| Portable Export (COGX-inspired) | JSON export of observations, graph edges, and embeddings for data portability; COGX-inspired format with `id`, `type`, `content`, `metadata`, `embeddings`, `graph_ref` per record; `mem export` CLI subcommand. | `014` portable-export step; `mem export --file`. | "data dump" (no structure); "JSON serialization" (too generic). |
| Dream Executor | Decompose distillation into `consolidate` (merge facts), `synthesize` (create summaries), `prune` (remove low-importance data); `DreamLockService` ensures single dream per project; `DreamRollback` reverts on failure. Based on ByteRover's DreamExecutor. | `014` dream-executor step; `brv dream` equivalent. | "memory consolidation" (vague); "distillation" (monolithic — no phase separation). |
| Importance Scoring (AKL) | Adaptive Knowledge Lifecycle: importance_score + maturity_tier + recency_decay per observation; feeds into query-time ranking in `mem_search`. Based on ByteRover's AKL. | `014` importance-scoring step; `mem search` ranking. | "TTL" (time-only); "relevance" (too vague). |
| Explicit Relations | `@relation` typed edges between observations (mentions, depends_on, contradicts, supports, references); queryable via `mem relations` CLI. Based on ByteRover's Context Tree relations. | `014` explicit-relations step; `mem relations` CLI. | "graph edges" (codeindex-only); "embedding similarity" (no semantics). |
| Provenance Chain | Immutable JSON metadata on observations: `session_id → curate_command → source_files → LLM_reasoning`; tracks why a memory was stored. Based on ByteRover's provenance tracking. | `014` provenance-tracking step; `mem provenance` CLI. | "metadata" (no chain); "audit log" (too broad). |
| Federated Query | Cross-project search with importance ranking + dedup; each store returns importance-scored results; merge pipeline applies cross-store rank. Based on ByteRover's SwarmCoordinator. | `014` federated-query step; `brv search` equivalent. | "parallel search" (no ranking); "batch search" (no federation). |
| Distill Lock + Rollback | `DistillLockService` ensures only one distillation per project; `DistillRollback` reverts observations to pre-distill state on failure. Based on ByteRover's DreamLockService. | `014` distill-lock step; `brv distill status`. | "locking" (too generic); "transaction" (DB concept). |
| Memory Types (OpenViking) | Typed observation categories: profile, preferences, entities, events, identity, soul, cases, trajectories, experiences; LLM dedup before write; async two-phase commit (sync write + async LLM extraction). Based on OpenViking's memory types. | `014` memory-types step; `mem types` CLI. | "tiers" (depth, not category); "tags" (too generic). |
| Directory Retrieval (OpenViking) | Hierarchical retrieval: find highest-scoring directory first, drill down layer by layer; observable retrieval trajectory preserved. Based on OpenViking's directory recursive retrieval. | `014` directory-retrieval step; `mem search --trajectory`. | "flat search" (no hierarchy); "tree view" (UI only). |
| Snapshots + Transaction Locking (OpenViking) | Point-in-time store snapshots; row-level locking for concurrent access. Based on OpenViking's multi-version management. | `014` snapshots step; `mem snapshot` CLI. | "backup" (too broad); "MVCC" (too heavy). |

| Hub Files + Impact Analysis (codemap) | Hub file identification (3+ importers); impact analysis based on changes to hub files; risk_score on observations. Based on codemap's hub file analysis. | `014` hub-impact step; `mem graph --risk`. | "dependency graph" (no impact); "risk" (no hub analysis). |
| Skills + Lifecycle Hooks (codemap) | Markdown-based skills matched by intent, mentioned files, project languages; lifecycle hooks (session-start, pre-edit, prompt-submit, session-stop) for context injection. | Memfs (OpenViking adaptation) | Virtual filesystem over the code index (files/symbols/chunks); `mem fs ls`, `mem fs tree`, `mem fs find`, `mem fs cat` walk repo paths (`memfs://project/{id}/...`, files addressed as `<file>::<symbol>`). Based on OpenViking's VikingFS browse paradigm. | `2026-09-18-memfs-code-index`; `mem fs` CLI. | "mem list" (flat observations); "file system" (too generic); "memory fs" (memfs is the code index, not the observation store). |
| Bi-temporal | A two-axis time model on observations: `valid_at` (when the fact became true) and `invalid_at` (when it stopped being true, NULL = still true). Superseded observations are excluded from search by default; time-travel queries use `valid_at <= T AND (invalid_at IS NULL OR invalid_at > T)`. Extends the `Temporal Knowledge Graph` (unary, codeindex edges only) to the observation store. | ADR-0011; bi-temporal columns on `observations`; auto-supersede on save. | "temporal" alone (ambiguous with `Temporal Knowledge Graph`); "versioned" (implies full versioning); "TTL" (time-only, no validity window). |
| Supersede | The domain verb for replacing a fact: a new observation supersedes an old one when the old fact is no longer true. Produces a chain: old gets `invalid_at` + `superseded_by` + `status='superseded'`; new gets a `supersedes` edge in `memory_relations`. Triggered automatically by the AUDN Delete arm on save. | ADR-0011; save cascade Delete arm; `MarkSuperseded`; `memory_relations` `supersedes` edge. | ADR-level `supersedes:` frontmatter (that's the index convention, not the domain verb); "replace" (too vague — implies hard delete); "update" (that's the AUDN Update arm, a content rewrite, not a validity change). |
| AUDN | The save-time classification of a memory write: Add (new fact), Update (refine existing), Delete (new fact supersedes old), Noop (duplicate, no change). Implemented by the `DedupLLM.Classify` seam; the deterministic floor (no LLM) maps hash-hit→Noop, hash-miss→Add. The Delete arm produces the supersede chain. | ADR-0011; `DedupLLM.Classify`; `SaveWithAction` 4-way routing; `mem_save` response `action` field. | "dedup" (only the Noop arm); "classification" (too vague); "routing" (implies network). |

 | Cited Floor | The deterministic, no-LLM answer path of `mem_ask`: blended search (FTS5 + vector RRF, degrades to keyword with `degraded=true`), token-bounded citation selection, `matched_via` discriminator. Always available; the fail-open destination of llm mode. | `secondbrain/ask.go`; `BlendedSearch` `degraded` flag; ADR-0016 response-shape convention. | "fallback" (implies error only); "keyword search" (only the degraded leg); "grounding" (the LLM-side property). |
 | Metadata Inference (`infer`) | The opt-in `mem_save` param (default off): deterministic fill of empty `type`/`topic_key` metadata from content signals (reuses `shapePassiveItem` + the `SuggestTopicKey` logic). Agent-provided values are never overwritten. | ADR-0016; `secondbrain/infer.go` `InferType`/`InferTopicKey`/`ApplyInfer`. | "classification" (too vague — AUDN is save-time action classification); "tagging"; "auto-detect" (marketing term). |
 | lifecycle_log | The 043 audit table: one row per mutating `mem_lifecycle` op (pending → completed/failed, `completed_at`, input/output ids, details). Append-only provenance for health/dedup/consolidate/archive. | ADR-0016; migration `043_lifecycle_log.sql`; `secondbrain/lifecycle.go` `logLifecycle`. | "audit trail" (generic); "history" (ambiguous with observation history); "log" (implies stdout). |
| Search Signals | The additive `signals` object on a `mem_search` hit: `keyword`, `vector`, `recency`, `entity`, `decay`, `importance`, each in [0,1], plus `matched_via` (`keyword` \| `vector` \| `hybrid`) and a fusion `score`. | ADR-0018; `memory.SearchHit`; `observationDTO`. | `_rank` (pinned/importance only); `mem_ask` citations. |
| Reinforcement Decay | Query-time rank factor `base × max(1, ln(1+retrieval_usage)) × 0.5^(days/half_life)`. Immune (half-life term = 1) when importance ≥ 4 or retrieval_usage ≥ 3. Days come from `LastSeenAt` only. | ADR-0018; `mnemonic.decay`; `rankByDecay`. | AKL `importance_score` formula (014 step 13, stored column); TTL. |
| Entity Alias | A case-insensitive alternate name for a code-index symbol `qualified_name`, stored in `entity_aliases` and checked before chunk FTS. | migration `045_search_aids.sql`; `codeindex` alias lookup. | `symbol_segments` (name parts, not free-text aliases). |
