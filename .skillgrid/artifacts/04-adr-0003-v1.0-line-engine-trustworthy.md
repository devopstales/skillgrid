# v1.0 line is "the engine is trustworthy"; UI is Phase 2

---
status: "accepted"
supersedes: none
date: 2026-09-16
---

## Context and Problem Statement

The PRD commits to a target state (not a pure description). The v1.0 line-in-the-sand had to be decided because it determines which current gaps are "known issues to fix before v1.0" and which are "Phase 2 roadmap." The embedded dashboard is a shell with every page a `StubPage` ("Coming in Phase N"); the tracker has 501s; the process-pass LLM labeler is a deterministic stub. Shipping those as "v1.0" would make the PRD's target-state claim false.

## Considered Options

- **Core engine + installer solid** — install idempotent on 3 agents, `doctor --strict` green, `mcp`/`serve` stable, index/search/code-intel reliable, mem/session/trail working; UI still stubs (explicitly "Phase 2")
- **Core + a working dashboard** — at least Memories + Sessions pages real, tracker functional (no 501s)
- **Core + dashboard + live LLM process labeling**

## Decision Outcome

Chosen option: "Core engine + installer solid," because v1.0's claim is "the
engine is trustworthy" — that is verifiable with the tools that already exist
(`install_test.go`, `doctor --strict`, `eval`, the staleness gate). A v1.0 gate
on UI pages or LLM labeling would either (a) require building the dashboard in
v1.0 scope (expanding the PRD beyond "engine trustworthy") or (b) lower the
claim to "engine works, UI is decorative." The dashboard and LLM labeling are
real work but they are enhancements to a trustworthy engine, not the
trustworthiness itself.

### Consequences

- Good, because v1.0 is testable: each claim maps to an existing test or a
  fresh-machine install run; no invented numeric thresholds.
- Good, because the roadmap (UI pages, tracker 501s, LLM labeling, `ui:build`
  task, README alignment, stray-repo cleanup) is a clean list of "Phase 2+"
  items, not a blur of "v1.0-ish" work.
- Bad, because users who install v1.0 will see stub dashboard pages and must
  trust that the engine underneath is the real product — the PRD and user
  guide must make that explicit.
