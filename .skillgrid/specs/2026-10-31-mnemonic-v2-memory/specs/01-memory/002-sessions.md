# 002 — Sessions

**Status:** DRAFT · **Owner:** memory change
**Depends on:** `002-schema` (§2.1)
**Reference:** Engram session lifecycle (`internal/store/session_finalize.go`,
`runtime_lease_expires_at`, resume continuations), the six-section summary; mnemonic v1
`mem_session_*` + the six-section structure.

---

## 1. Capability

Sessions group the observations, prompts, and relations from one agent session. A
session is the **provenance root** (INV-1) — every fact points back to the session that
wrote it. Sessions also carry the **structured summary** that is the raw input to the
wiki's distillation (a wiki-side concern, `03-llm-wiki`; the memory function does not
own the distillation hierarchy).

## 2. Session lifecycle

```
mem_session_start({id, project, directory, ownership_mode, resume, isolated})
   │  registers a session row; sets runtime_lease_expires_at (30 min, local-only)
   ▼
agent works → mem_save / mem_save_prompt / mem_judge  (all reference the session)
   │
   ▼
mem_session_summary(six-section)        → writes a type=session_summary observation
   │                                      (does NOT end the session)
   ▼
mem_session_end(summary?)               OR  mem_session_finalize(atomic)
   │  sets ended_at → session is TERMINAL
   ▼
next session: mem_context (or a plugin injects prior context)
```

## 3. Identity and terminal semantics

- **Session `id` is byte-exact, never trimmed** (Engram). It is the provenance anchor.
- **Ended sessions are terminal** — never reopened. Ending an ended session → `409
  session_already_ended`.
- **Runtime identity** (for runtimes like Codex): startup registers a resumable root;
  writes/prompt-capture/compaction resolve an existing active identity; runtime closing
  resolves and ends atomically without creating a continuation. Adapters forward the
  acknowledged id; they maintain no identity cache.
- **Resume:** `resume: true` on `mem_session_start` atomically selects/creates an
  `<id>:resume:N` continuation **inside one write transaction**, preserving the terminal
  root, ownership checks, and runtime leases. The adapter forwards the returned id — it
  does not choose the suffix.

## 4. Ownership modes

| Mode | Meaning |
|---|---|
| `shared` (default) | the session's project is shared; observations inherit the project |
| `project_owned` | the session is bound to one project; cross-project writes are refused |

Cross-project satellite sessions (e.g. `<runtimeID>@<project>`) are a runtime-adapter
concern (pi-plugin), not a store concept.

## 5. The six-section structured summary

`mem_session_summary` writes a `type=session_summary` observation with content in the
**six-section structure** (v1's contract, retained):

```
## Goal
## Instructions
## Discoveries
## Accomplished
## Next Steps
## Relevant Files
```

All six must be filled (a red-flag check in v1's protocol). This observation is:
- **not** the session's `summary` column (that's legacy free-text);
- the **raw input** the llm-wiki's distillation reads (the "what did this session
  accomplish" record) — a wiki-side concern, not owned here;
- attributed to the session (provenance).

**Summary persistence does not itself end a session** (Engram). The host retains its own
attribution/registration/privacy/lifecycle obligations.

## 6. `mem_session_finalize` — atomic close

`Store.FinalizeSession` (Engram `session_finalize.go`) does, in **one transaction**:
1. inserts the `session_summary` observation (if not already present),
2. sets `ended_at`,
3. enqueues the sync mutations,
4. records `session_finalizations` (local-only idempotent retry journal) so a retry
   returns `already_finalized: true` instead of double-closing.

This is the strong close. `mem_session_end` is the weaker free-text close. Both exist;
the agent protocol prefers finalize at significant closure.

## 7. Liveness (local only)

`runtime_lease_expires_at` (30 min) is a **local liveness** marker, refreshed on each
create/renew. It is **never synced** and never replicated. A stale lease means the
runtime is presumed gone; it does not end the session (only explicit end/finalize does).

## 8. What is captured (and what isn't)

- **Captured:** per-event — observations + prompts + relations during the session, and
  the session summary. Not a transcript.
- **Compaction:** not model-generated by the store. After a host compaction, the agent
  (per its protocol) persists the compacted summary first, recovers via `mem_context`,
  then continues. `mem_context.older_history` provides the calendar-structure recall.

## 9. Invariants

INV-1 (session is the provenance root), INV-6 (session `sync_id` for replication),
INV-4 (local lease is local-only).
