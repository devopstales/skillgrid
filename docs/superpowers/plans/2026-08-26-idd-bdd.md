# IDD + BDD Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship IDD and BDD as superpowers-augmenting skills in `config.d/skills/`, register them via `skills.paths`, install zone-guard + rules, with no OpenSpec dependency.

**Architecture:** Vend/adapt skills into `config.d/skills/`. Flat **`docs/superpowers/{proposal,specs,adr,plans}/`** layout — dated files sharing `YYYY-MM-DD-<topic>` slug. Gherkin in `specs/*-design.md`. Archive via plan `STATUS: ARCHIVED` + design `STATUS: DECIDED`.

**Tech Stack:** Markdown skills, shell (zone-guard), Node (cucumber-js reference pack), Go (skillgrid-cli).

**Spec:** `docs/superpowers/specs/2026-08-26-idd-bdd-design.md`

## Global constraints

- No OpenSpec CLI, no `openspec/` paths, no schema bundles.
- All project artifacts under `docs/` (superpowers, glossary, acceptance-tests); zone root = `docs/`.
- `.feature` files are extracted from `-design.md` — not hand-edited source of truth.
- `config.d/` is source of truth for skills, hooks, rules — not `docs/superpowers/`.
- Do not vend `test-driven-development`; use superpowers.
- Install-step failures: `logging.Warn`, never fatal.
- `--dry-run` logs planned actions; no writes/exec for IDD/BDD step.
- Re-run install is idempotent (skills.paths, AGENTS markers).
- Verification bar: `go build ./... && go test ./...` in `skillgrid-cli/` after CLI tasks.
- Commit messages: short imperative (e.g. `feat: register local IDD/BDD skills path`).
